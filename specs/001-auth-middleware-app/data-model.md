# Data Model: Centralized Authentication Gateway

## Entities

### User

Represents a person who may authenticate via this service.

| Field           | Type         | Constraints                              | Notes |
|-----------------|--------------|------------------------------------------|-------|
| `id`            | UUID         | PK, default gen_random_uuid()            | |
| `username`      | VARCHAR(100) | UNIQUE, NOT NULL                         | Used for password login |
| `email`         | VARCHAR(255) | UNIQUE, nullable                         | Required for OAuth matching; NULL for password-only accounts |
| `password_hash` | VARCHAR(255) | nullable                                 | NULL for OAuth-only accounts; bcrypt hash |
| `role`          | VARCHAR(20)  | NOT NULL, CHECK IN ('admin', 'user')     | |
| `is_active`     | BOOLEAN      | default TRUE                             | FALSE = blocked; cannot authenticate |
| `google_id`     | VARCHAR(255) | nullable                                 | Stored after first successful Google login |
| `github_id`     | VARCHAR(255) | nullable                                 | Stored after first successful GitHub login |
| `created_at`    | TIMESTAMP    | default NOW()                            | |

**Validation rules**:
- `username` must be non-empty and unique across all users.
- At least one of `password_hash` or `email` must be set (a user must be able
  to log in by some method).
- `role` is set at creation time and can only be changed by direct admin action
  (no self-promotion).

**State transitions**:
- `is_active: true → false` (block): triggers immediate token invalidation.
- `is_active: false → true` (unblock): user can authenticate again; no tokens
  are restored.

### UserAppAccess

Maps a user to a protected application with an enabled/disabled flag.

| Field        | Type         | Constraints                                   | Notes |
|--------------|--------------|-----------------------------------------------|-------|
| `id`         | UUID         | PK, default gen_random_uuid()                 | |
| `user_id`    | UUID         | FK → users(id) ON DELETE CASCADE, NOT NULL    | |
| `app_name`   | VARCHAR(100) | NOT NULL                                      | One of the 8 protected app identifiers |
| `is_enabled` | BOOLEAN      | default FALSE                                 | |

**Unique constraint**: `(user_id, app_name)` — one row per user-application pair.

**Known app_name values** (the 8 protected applications):
```
budget-site
family-admin-routine
family-archive
family-kitchen-recipes
new-site
portuguese-expenses
reminders-app
servinga-dashboard
```

**Behaviour**:
- When a new user is created, `UserAppAccess` rows for all 8 applications are
  inserted with `is_enabled = FALSE`. The admin then enables access as needed.
- The `apps` array returned by `/api/verify-token` is the list of `app_name`
  values where `is_enabled = TRUE` for the authenticated user.

### AuthToken

An opaque session token issued after successful authentication.

| Field          | Type         | Constraints                                | Notes |
|----------------|--------------|--------------------------------------------|-------|
| `id`           | UUID         | PK, default gen_random_uuid()              | |
| `token_value`  | VARCHAR(128) | UNIQUE, NOT NULL                           | 64-hex-char random string (32 bytes → 64 hex) |
| `user_id`      | UUID         | FK → users(id) ON DELETE CASCADE, NOT NULL | |
| `expires_at`   | TIMESTAMP    | NOT NULL                                   | `created_at + TOKEN_TTL_HOURS` |
| `created_at`   | TIMESTAMP    | default NOW()                              | |
| `last_used_at` | TIMESTAMP    | nullable                                   | Updated on every successful verification |

**Validation rules**:
- `token_value` is generated by `secrets.token_hex(32)` (Python stdlib);
  never user-supplied.
- `expires_at` is computed at issuance from `TOKEN_TTL_HOURS` env variable.

**Lifecycle**:
1. Created on successful authentication.
2. `last_used_at` updated on every successful `/api/verify-token` call.
3. Deleted (invalidated) when: user is blocked, explicit logout, hourly cleanup
   of expired tokens.

### AuthLog

Immutable audit record of every authentication attempt.

| Field        | Type         | Constraints       | Notes |
|--------------|--------------|-------------------|-------|
| `id`         | UUID         | PK, default gen_random_uuid() | |
| `username`   | VARCHAR(100) | nullable          | As provided by the user; may not match a real account |
| `ip_address` | VARCHAR(45)  | nullable          | IPv4 or IPv6; extracted from `X-Real-IP` header |
| `method`     | VARCHAR(20)  | nullable          | One of: `'password'`, `'google'`, `'github'` |
| `success`    | BOOLEAN      | NOT NULL          | |
| `reason`     | VARCHAR(255) | nullable          | Populated on failure: e.g. `'invalid_password'`, `'user_blocked'`, `'unknown_oauth_email'` |
| `created_at` | TIMESTAMP    | default NOW()     | |

**Immutability**: No UPDATE or DELETE operations are ever issued against this
table by application code. Rows are INSERT-only.

## Entity Relationships

```
users (1) ──────── (many) user_app_access
  │                         (user_id FK)
  │
  └── (many) auth_tokens
               (user_id FK)

auth_logs  ← no FK; records username as a string (may reference deleted users)
```

---

## Database Ownership

`auth-app` owns these four tables exclusively. No other service may write to
them. All tables reside in the shared PostgreSQL instance from `web-folders`
under the database `maindb` (or as configured in `DATABASE_URL`).

---

## Migration Strategy

- Managed by Alembic (autogenerate from SQLAlchemy models).
- `alembic upgrade head` runs automatically on every deployment.
- `db/seed.py` runs post-migration on first deployment; it checks whether the
  `users` table is empty before inserting seed rows (idempotent).
- Seed data comes entirely from environment variables; no defaults are
  hardcoded in the seed script.
